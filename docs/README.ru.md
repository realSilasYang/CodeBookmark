CodeBookmark — расширение VS Code для разметки кода и навигации. Механизм привязки связывает конфигурацию с идентичностью скрипта и заново находит закладки после правок, переименования файлов, перемещения папок или переноса workspace. Данные остаются в выбранной локальной папке. ИИ может создавать закладки по смыслу кода, улучшать подписи и выбирать значок только при однозначном соответствии.

# Руководство пользователя

## 1. Первичная настройка

Укажите `Codebookmark: Global Storage Path`. Это должна быть постоянная локальная папка с правом записи, отдельная от исходников и временных каталогов. При открытии одного файла показываются только его закладки; для папки или workspace отображаются файловые узлы, обычные закладки и межфайловая раскладка. Ничего не передаётся наружу, кроме выбранного кода при явном запуске команды ИИ.

## 2. Клавиши и навигация

`Ctrl+B`／`Cmd+B` добавляет или удаляет закладку текущей строки; `Ctrl+Alt+B`／`Cmd+Alt+B` принудительно добавляет, а `Ctrl+Alt+Shift+B`／`Cmd+Alt+Shift+B` удаляет. Узел хранит подпись, строку, точный якорь, иерархию, значок, раскрытие и стабильный ID. Переход использует уже открытую вкладку или открывает новую непредварительную вкладку.

## 3. Иерархия, перетаскивание и контейнеры

Закладки и файловые узлы можно сортировать, переименовывать, снабжать значками, превращать в контейнеры и вкладывать друг в друга. Межфайловое перетаскивание не смешивает данные: у каждого скрипта остаётся своя конфигурация, а `_workspace_layout.json` хранит только порядок, отношения, скрытие, контейнеры и раскрытие. Удаление файлового узла никогда не удаляет исходник; после подтверждения удаления визуального поддерева обычные закладки действительно удаляются из конфигураций-владельцев.

## 4. Поиск, подписи и значки

Поиск охватывает подписи, имена, пути и код. Для подписей в редакторе настраиваются цвет, размер, начертание, интервалы и позиция. Выбор значка поддерживает категории, нечёткий поиск на китайском и английском, постраничную загрузку и недавние значки с синхронизацией VS Code. При неоднозначности ИИ сохраняет стандартный значок.

## 5. Автоматические TODO, FIXME и BUG

Это не простой поиск текста. Язык должен зарегистрировать в VS Code grammar подсветки и официальные правила комментариев, а директива должна начинать настоящий комментарий. Имена SVG, метаданные JSON, строки, обычный текст, Plain Text и файлы без подсветки исключены. Сканирование ограничено 2 000 файлами, пропускает закрытые файлы свыше 2 МиБ, допускает 5 000 автоматических меток на скрипт и 10 000 узлов на конфигурацию.

## 6. Перемещение и восстановление

Идентичность складывается из ID скрипта, относительного пути, признаков содержимого, журнала перемещений и состояния отсутствия. Поддерживаются переименования VS Code, внешние перемещения, целые папки, отдельные скрипты и удаление с последующим созданием без события rename. Автопривязка выполняется только при единственном надёжном кандидате. Для строки сравниваются якорь, окружение, структура и расстояние; при нехватке доказательств узел помечается недействительным.

## 7. Импорт, экспорт и управление

Команда «Импорт／экспорт закладок» сохраняет текущий скрипт или рабочую область в одном файле конфигурации `.codebookmark`. Его можно импортировать в другую локальную папку либо на устройство с Windows, macOS или Linux, отредактировать и передать дальше без потери подписей, значков, иерархии, якорей кода, оформления файловых узлов и межфайловой структуры. Пакет не содержит абсолютных путей и идентификаторов файловой системы; прежние JSON-файлы и каталоги конфигураций больше не поддерживаются для импорта.

При импорте тип пакета определяется автоматически, а привязка выполняется только к единственной надёжно найденной цели по относительному пути, хешу исходника или контексту закладок. Неоднозначные совпадения отмечаются как конфликты; при наличии закладок можно выбрать добавление или перезапись. Markdown, HTML, CSV и иерархический текст остаются форматами только для чтения. Менеджер также показывает записи обмена между устройствами, структуры, миграции, конфликтные копии и временные остатки.

## 8. Помощь ИИ

Настройте `Codebookmark.AI: Address`, `API Key` и модель. Address принимает Resource Endpoint, API Base URL, Chat Completions, Responses, Anthropic Messages, Gemini `generateContent` и Ollama; после успешной проверки сохраняется реально сработавший адрес. Для удалённых служб нужен HTTPS. ИИ создаёт закладки для текущего скрипта или скриптов без закладок в workspace, а также добавляет, пересоздаёт и улучшает подписи существующих. Меню автоматически скрывает неприменимые действия.

Ответ проверяется по структуре JSON, строке, буквальному якорю, количеству, глубине, владельцу ID и списку значков. Код и имена — данные, а не инструкции. В недоверенном workspace ИИ отключён; отмена, timeout, изменение файла во время анализа или превышение лимита исключают частичное применение.

## 9. Отмена, повтор и конфликты

Создание, удаление, переименование, перетаскивание, сортировка, контейнеры, значки, ИИ, импорт и пакетные действия создают атомарные записи по scope. Запись проходит через очередь на файл, обнаруживает внешние изменения и атомарно заменяет цель. Смена хранилища сначала копирует и проверяет данные, затем переключается и только после этого очищает перенесённые файлы старого каталога.

## 10. Основные параметры

`globalStoragePath` задаёт хранилище; `defaultIcon`, `showLineNumber` и `showLabelInEditor` управляют отображением; `codeMarkers.enabled` включает автоматические метки. Для ИИ служат `AI.address`, `AI.APIKey`, `AI.model` и `AI.assignIcons`.

# Руководство разработчика

## 1. Структура и активация

`src/` содержит TypeScript, `scripts/` — сборку, проверки, интеграцию и выпуск, `tests/` — unit, contract и Extension Host тесты, `resources/` — ресурсы. `package.json`, `out/` и `package.nls*.json` генерируются; источники манифеста — `BasePackage.ts` и `Commands.ts`. `extension.ts` инициализирует локализацию, настройки, репозиторий, Provider, команды и подписки. Видимость определяется стабильными Context Key, а не переводами.

## 2. Модель, хранение и файлы

`Bookmark`, `BookmarkSet` и codec задают идентичности и иерархии. У каждого скрипта своя конфигурация, а `_workspace_layout.json` описывает только межфайловую раскладку. `PersistenceSchema` и миграции проверяют данные. `BookmarkRepository`, `ScriptRelocationJournal` и подписки обрабатывают перемещения. Записи сериализуются, сверяют прочитанную версию и заменяют цель через временный файл.

## 3. Слежение, отмена и безопасность

Механизм принимает только единственный сильный кандидат позиции. Отмена использует полные снимки; межфайловая операция включает все затронутые конфигурации и раскладку. `AIService` отвечает за адреса и транспорт, schemas — за недоверенные ответы, каталог — за семантический допуск значков. Автометки требуют grammar и правил комментариев. Webview используют nonce, строгий CSP и структурированные сообщения.

## 4. Сборка, тесты и выпуск

Проект использует Node.js 24. `npm run verify` запускает компиляцию, ESLint, модульные и контрактные тесты и все проверки, применимые во время разработки; `npm run verify:release` проверяет окончательные материалы версии. `npm run test:integration` повторно использует установленный VS Code в изоляции для 13 языков и английского варианта по умолчанию; `npm run check:release` объединяет все эти проверки с аудитом и просмотром состава VSIX.

Публикуются только аннотированные теги из истории `main`. GitHub Actions использует краткоживущие OIDC-данные, публикует Marketplace, сравнивает хеш удалённого VSIX и создаёт Release только с VSIX, без SBOM и `SHA256SUMS`. См. [руководство по выпуску](https://github.com/realSilasYang/CodeBookmark/blob/main/docs/release/RELEASING.en.md).
